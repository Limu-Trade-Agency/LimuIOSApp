CAPTURE METHOD AND SCOPE
Native SwiftUI/UIKit renders from the current local working tree, including its uncommitted UI changes, in an isolated screenshot build on the iPhone 17 Pro / iOS 26.5 simulator. These are app-view snapshots, not redesigned mockups. The production source was not edited for this capture task.
The app's bundled demo records and synthetic contact details populate the screens. Authentication/KYC states are initialized directly; no real registration, verification, password change, or order action was submitted.
Scrollable stacks are fully laid out in the capture build so long exports include all rows. Main app captures retain the top navigation and native bottom tabs. System status-bar time, battery, keyboard, and home indicator are not part of these app-view exports.
Picker and verification-sheet contents are shown standalone for implementation reference; presentation dimming and half-height sheet surroundings are not captured. The components page is a reference composition of the real reusable components, not an app navigation destination.
The photo preview includes the actual image-unavailable state because the bundled order examples contain no product photographs. Network-specific error wording, live-photo content, OS permission dialogs, keyboard variants, animations, and every possible data combination are outside this static visual pack.

Navigation is Home / Cargo / Shipments / Order Forms / Profile, with global Notifications. The latest source uses Order Forms for purchasing/financial information; it has no separate Invoices view.
Capture the current screenshots faithfully. Earlier project notes mention a copper/peach palette, but the current DesignSystem.swift maps copper to sunset orange and peach to yellow.

Section headings: 11-point bold, uppercase, tracking 0.7. Field labels: 12-point semibold, uppercase, tracking 0.6. Primary buttons: 15-point bold with 14-point vertical padding. Disabled gradient opacity: 0.48.
